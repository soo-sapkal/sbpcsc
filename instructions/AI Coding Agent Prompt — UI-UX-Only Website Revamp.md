# UI/UX-Only Website Revamp — Master Prompt

You are an expert **senior UI/UX designer, frontend architect, interaction designer, and creative developer**. Your task is to completely **visually revamp the existing website** while preserving its existing information architecture and content with absolute fidelity.

The website is a **professional college/institutional website**. The goal is to make it feel significantly more modern, premium, polished, engaging, responsive, and memorable **without changing what the website says or how its information is organized**.

---

## 1. PRIMARY OBJECTIVE

Perform a **UI/UX transformation only**.

The existing website is the source of truth for:

- Content
- Pages
- Sections
- Section order
- Navigation structure
- Information hierarchy
- Text
- Headings
- Labels
- Buttons
- Links
- Forms
- Data
- Images, unless their presentation is being visually improved
- Functional behavior, unless required for improved UX
- Existing routes/pages

The revamp should change **how the website looks and feels**, not **what information it contains**.

Think:

> **Same website. Same information. Completely different visual experience.**

Do NOT interpret "revamp" as permission to rewrite, reorganize, consolidate, remove, relocate, or invent content.

---

# 2. ABSOLUTE CONTENT PRESERVATION RULE

This is the most important constraint.

### DO NOT:

- Rewrite existing copy
- Paraphrase text
- Change headings
- Change terminology
- Add marketing copy
- Add slogans
- Add unnecessary descriptions
- Invent statistics
- Invent testimonials
- Invent achievements
- Invent departments
- Invent programs
- Invent faculty
- Invent events
- Invent testimonials
- Invent FAQ entries
- Invent CTAs
- Remove existing information
- Move content from one page to another
- Merge pages
- Split pages
- Change section ordering
- Replace meaningful content with placeholder content
- Create fictional UI content
- Add generic AI-generated filler

### DO:

Preserve the existing website's:

**Page → Section → Content hierarchy**

exactly.

If the original homepage contains:

1. Hero
2. About
3. Departments
4. Programs
5. News
6. Events
7. Contact

the revamped homepage must still contain those same sections in the same logical order.

You may radically redesign the **visual treatment** of those sections.

For example:

- A traditional hero can become an immersive cinematic hero.
- A basic card grid can become an interactive editorial grid.
- A plain image section can become a layered image composition.
- A basic news list can become a sophisticated timeline.
- A conventional gallery can become a horizontal scrolling gallery.
- A basic statistics row can become animated data counters.
- A simple navigation bar can become a refined responsive navigation system.

But the underlying content must remain identical.

# 18. PERFORMANCE

- transform
- opacity
- compositor-friendly properties

- layout thrashing

- huge image payloads
- unnecessary libraries
- expensive continuous scroll handlers

Use lazy loading where appropriate.

Optimize existing assets where possible.

# 38. EXECUTION ORDER

Follow this workflow:

### Phase 1 — Audit

Understand the complete existing website.

### Phase 2 — Content Lock

Treat all existing content and page structures as immutable.

### Phase 3 — UX Analysis

Identify usability problems without changing information architecture.

### Phase 4 — Design System

Establish typography, colors, spacing, shapes, grids and motion.

### Phase 5 — Visual Concepts

Explore multiple possible visual directions.

### Phase 6 — Page Redesign

Redesign each page while preserving its exact content structure.

### Phase 7 — Interaction Design

Add meaningful animations and micro-interactions.

### Phase 8 — Responsive Design

Optimize every page for desktop, tablet and mobile.

### Phase 9 — Accessibility

Verify keyboard navigation, contrast, focus states and reduced motion.

### Phase 10 — Performance

Optimize images, animation and rendering.

### Phase 11 — Content Integrity

Compare redesigned pages against the originals.

### Phase 12 — Final QA

Test the entire website as a real user.

# 39. CRITICAL RULE

Whenever you are uncertain whether a proposed change is a **content change** or a **visual/UX change**, choose the conservative option.

The question should always be:

> "Can I achieve this improvement without changing the information architecture or content?"

If yes, do it.

If no, **do not make the change.**
